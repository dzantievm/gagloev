# Фильтрация рейтинга по месяцам

## Context

Нужен рейтинг с фильтром по месяцам («Всё время» / 1-й / 2-й / ... месяц), чтобы видеть, кто больше всего набрал именно в конкретном месяце.

Первая попытка была откачена — вся логика (парсинг CSV, диапазоны периодов, streak-проверки) была размазана по реактивным `computed` прямо внутри `index.vue`, вперемешку с UI, и трудно было проверить, что ничего не поехало. Дело не в том, *где* считать (на лету или заранее) — считать по-прежнему можно на лету, при каждой загрузке страницы, данные всё равно фетчатся из `result.csv`. Дело в том, что расчёт должен быть отдельно от UI-слоя.

Новый подход — разнести по слоям, а не по времени вычисления:
1. **Конфиг** — какие месяцы существуют, сколько дней в каждом, какие колонки `result.csv` им соответствуют. Задаётся руками.
2. **Чистый расчётный модуль** (обычный `.ts`-файл без Vue-реактивности) — на вход CSV-текст + конфиг, на выходе готовые таблицы по всем вкладкам. Функция, которую можно вызвать и проверить в изоляции от Vue, до того как она попадёт в UI.
3. **Фронтенд** — при монтировании фетчит `result.csv`, один раз вызывает расчётный модуль, кладёт результат в `ref`, дальше только переключает вкладки без пересчётов.

## Промт 1 — Конфиг месяцев

Создать файл `frontend/utils/monthsConfig.js`. Экспортировать массив `MONTHS`:

```js
// Настройки месячных вкладок рейтинга.
// key — ключ вкладки, fromPeriod/toPeriod — префиксы колонок в result.csv
// (result.csv генерируется merge.js как `${prefix}-file;${prefix}-streak;${prefix}-xp`,
// префиксы там: start, 1m, 2m, 3m, 4m, ...), days — ожидаемое число дней между
// чекпоинтами, порог непрерывности streak для этого месяца.
export const MONTHS = [
	{ key: '1m', label: '1 месяц', fromPeriod: 'start', toPeriod: '1m', days: 30 },
	{ key: '2m', label: '2 месяц', fromPeriod: '1m', toPeriod: '2m', days: 30 },
	{ key: '3m', label: '3 месяц', fromPeriod: '2m', toPeriod: '3m', days: 30 },
	{ key: '4m', label: '4 месяц', fromPeriod: '3m', toPeriod: '4m', days: 31 },
]
```

`fromPeriod`/`toPeriod` обязаны совпадать с префиксами, которые реально есть в заголовке `result.csv` — сейчас там `start, 1m, 2m, 3m, 4m` (проверено: `head -1 result.csv`). `days` заменяет нынешнюю захардкоженную константу 122/91 на весь период — то же самое, но по месяцам и настраиваемое руками.

При добавлении 5-го месяца конфиг правится вручную — одна новая строка `{ key: '5m', label: '5 месяц', fromPeriod: '4m', toPeriod: '5m', days: ... }`.

## Промт 2 — Чистый расчётный модуль

Создать `frontend/utils/leaderboard.js`. Каждая функция — с комментарием на русском, описывающим её назначение. Экспортировать одну точку входа `buildLeaderboards(csvText, months)`, возвращающую `{ tabs: [{key, label}], data: { [key]: { leaderboard: [...], dropped: [...] } } }`.

Внутри (приватные функции, не экспортируются):
- `parseCsvLine` — парсинг `;`-CSV строки с учётом кавычек (переиспользовать логику, уже написанную в текущем `index.vue`, не изобретать новую).
- `parsePlayers(csvText)` — **как находим нужные колонки:** разбирает первую строку CSV (заголовок) на массив имён колонок и по каждому `period` из конфига ищет в этом массиве индексы колонок `${period}-streak` и `${period}-xp` через `indexOf` (а не по номеру колонки — так это не сломается, если порядок колонок в файле изменится). Возвращает список `{ username, periods: { [period]: { streak: number|null, xp: number|null } } }` по всем periods, встретившимся в конфиге (`start` + все `fromPeriod`/`toPeriod` из `MONTHS`).
- `classifyRange(players, fromPeriod, toPeriod, days, isAll)` — для одного диапазона (месяц или «всё время») распределяет участников на `leaderboard`/`dropped` по правилам:
  - нет `fromPeriod`-xp → `dropped`: «Не участвовал с начала конкурса» (для `all`) / «Нет данных за <label предыдущего периода>»
  - нет `toPeriod`-xp → `dropped`: «Не прислал результат» (для `all`) / «Не прислал результат за <label>»
  - `toPeriod.streak - fromPeriod.streak < days` → `dropped`: `Streak <факт> / <days> — пропустил день`
  - иначе → `leaderboard`: `{ username, fromXp, toXp, diff: toXp - fromXp }`, отсортировать по `diff` убыв.
- `buildLeaderboards` — добавляет к `months` одну сводную запись `all` (`fromPeriod = months[0].fromPeriod`, `toPeriod = months[months.length - 1].toPeriod`, `days = сумма days всех месяцев`), прогоняет `classifyRange` по всем записям, собирает `tabs`/`data`.

**Проверка:** временно вызвать `buildLeaderboards` в консоли браузера (или коротким `console.log` в `onMounted` перед тем как использовать результат в шаблоне) и сверить вручную участника `001610.095KMKS6` (пропустил скрин 3-го месяца, но прислал 4-й) — в `all` прирост должен быть `194028 - 129683 = 64345`.

## Промт 3 — Подключить к фронтенду

Переписать `frontend/pages/index.vue`:
- Убрать весь парсинг CSV и расчёт диапазонов/streak из компонента — вызывать `buildLeaderboards(text, MONTHS)` из `frontend/utils/leaderboard.js` и `monthsConfig.js`.
- В `onMounted` фетчить `/result.csv` (как сейчас), результат `buildLeaderboards` положить в `ref` целиком.
- Вкладки фильтра рендерить из `result.tabs` (кнопки — `filter-tabs`/`filter-tabs__item`/`filter-tabs__item--active`, BEM, стили на `$color-green`/`$color-border`, как в первой попытке).
- `leaderboard`/`dropped` для текущей вкладки — `result.value.data[filter.value]?.leaderboard` / `.dropped`, без пересчётов.
- Остальная разметка (`.stats`, `.leaderboard__row`, `.dropped`) и стили не меняются, только поля `player.startXp`/`player.finalXp` → `player.fromXp`/`player.toXp`.
- Подзаголовок в хедере — динамический: `Прирост XP за <label вкладки>`.

**Проверка:** `npm run dev` во `frontend`, вручную пройтись по вкладкам и поиску в браузере, сверить числа с промтом 2.

## Промт 4 — Финальная сверка

Пройтись по всем вкладкам, сверить состав и суммы. Проверить участников с пропущенными месяцами (например `001610.095KMKS6`) — они должны попадать в нужную вкладку/выпадать с понятной причиной, а не считаться через неверную колонку.

## Затрагиваемые файлы

- `frontend/utils/monthsConfig.js` — новый, конфиг месяцев
- `frontend/utils/leaderboard.js` — новый, чистый расчётный модуль
- `frontend/pages/index.vue` — использует модуль вместо собственного парсинга/расчётов
